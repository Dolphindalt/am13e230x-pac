# am13e230x-pac

Peripheral access crate for the Texas Instruments AM13E230x family (AM13E23017, AM13E23018, AM13E23019).

The register API is generated by [svd2rust](https://docs.rs/svd2rust).

## Usage

```toml
[dependencies]
am13e230x-pac = { version = "0.1", features = ["critical-section"] }
```

```rust
let p = am13e230x_pac::Peripherals::take().unwrap();
p.gpio0.gprcm().pwren().write(|w| w.key().unlock().enable().set_bit());
```

PWREN, RSTCTL and the other keyed registers ignore a write unless it also sets `key().unlock()`.

Enable `rt` in the final application, which also depends on `cortex-m-rt`. HAL crates usually forward it as their own `rt` feature.

## Features

| Feature | Effect |
|---------|--------|
| `rt` | Interrupt vector table (`device.x`) and the `#[interrupt]` attribute, via `cortex-m-rt` |
| `critical-section` | `Peripherals::take()` |
| `defmt` | `defmt::Format` for register values and enums |
| `debug` | `Debug` for register blocks and fields |

## Flashing the LP-AM13E230 LaunchPad

The LaunchPad's onboard XDS110 probe speaks CMSIS-DAP, so [probe-rs](https://probe.rs) can flash it. probe-rs has no built-in AM13 support; `probe-rs/am13e230x.yaml` is a chip description generated from TI's CMSIS pack. Use the probe-rs release that matches the target-gen version pinned in `xtask/src/main.rs`:

```sh
cd examples/lp-am13e230
cargo run --release --bin blinky   # flashes, runs, Ctrl-C to detach
```

`examples/lp-am13e230/.cargo/config.toml` sets the target, the `probe-rs run` runner and the chip description. To use it from your own project, pass `--chip AM13E23019 --chip-description-path <path>/am13e230x.yaml` to probe-rs.

## Development

`src/`, `svd/`, `build.rs`, `device.x` and `probe-rs/` are generated from `vendor/ti/` and `patches/`, and CI rejects hand edits. Run `cargo xtask` to list the commands.
